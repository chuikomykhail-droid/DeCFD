DeCFD · decentralized CFD on Solana · built at Dev3pack, November 2026

Industrial CFD on a Solana compute network, checked against TU Munich's cluster

SuperWing is a public dataset of 3D transonic wings from the Thuerey group at TU Munich, computed on a 160-core cluster. We recomputed one of its wings with the group's own pipeline (pyHyp mesh, ADflow RANS, 3.5 million cells) on a 16 GB laptop, and every flight condition came out as the cluster published it. The same computation now runs as tasks on DeCFD: miners compute in a pinned container, a verifier re-runs a sample and checks it within a tolerance, and a Solana program pays honest work and slashes fakes.

How the solution settles

Lift minus the cluster's final value, per fine-grid solver cycle. On 16 GB the authors' Newton-Krylov solver does not fit, so we ran the multigrid smoother; it needs more cycles but lands on the same answer. Each curve enters the tolerance band after about 1,000 cycles, roughly 55 minutes on this laptop.

How the network checks a RANS result

The job pins the pipeline

A job stores the hash of the container recipe: the MDO Lab image pinned by digest, the TU Munich scripts and our runner. A node computes with exactly that, the way the lattice-Boltzmann jobs pin their solver binary.

The task pins the case

Each task carries the wing, the flight condition and the solver settings, plus a hash over the case file. A node rebuilds the hash from its own copy and refuses a case that differs from the posted one.

Audits use a tolerance

An MPI solve does not repeat bit for bit, so the verifier re-computes a sample and accepts lift and drag within ±0.001 and ±1 count. On chain it then confirms the miner's commitment, or submits its own and the miner loses half its stake.
